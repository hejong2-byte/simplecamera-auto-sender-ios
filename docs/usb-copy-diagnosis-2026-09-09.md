# SD/USB 복사 정체 조사 (진행 기록)

## 사용자 화면에서 확인된 것

- ZIP 원본 8.09 GB, 압축 해제 결과 10.38 GB.
- 이전 실패: `2/2 · USB 복사 70/6683개`, `SD_CARD_ROOT/MAP.spd.000`, 무결성 검증 실패.
- 교체한 SD카드: `2/2 · USB 폴더 생성 41/474개`, `SD_CARD_ROOT/MAP/TPEG_IMAGE_NEW/00016`, 마지막 갱신 후 364초.
- 삭제를 처음 수행하면 65개 남았다고 표시하지만 다시 수행하면 완료. 실제 저장장치/리더기를 이 환경에서 재현하지 못함.

## 코드로 확인된 구분

- `SafeZIPExtractor`가 모든 항목을 해제하고 CRC를 확인한 후에만 `exportZIP`의 USB 폴더 생성으로 이동한다. 위 화면은 ZIP 해제 자체가 아니라 이후 USB 쓰기 단계다.
- 기본 복사 경로는 USB 재읽기 SHA 검증을 하지 않는다. `sizeMismatch`와 `shaMismatch`가 같은 '무결성 검증 실패' 문구를 쓰므로 화면만으로 SHA 불일치라고 해석할 수 없다.
- 진행 스트림은 `bufferingNewest(32)`로 제한되어 있다. 무제한 진행 알림 대기열이 원인이라는 가설은 현재 코드와 일치하지 않는다.
- 외부 폴더 접근권은 획득하지만 폴더 생성/파일 쓰기는 파일 조정자 없이 실행하고 마지막 이름 변경만 조정하고 있다.
- 삭제 후 목록 재확인은 1회뿐이며, 저장장치 제공자의 지연된 목록이 최종 잔여 개수로 표시될 수 있다.
- 폴더/파일 반복 처리의 임시 메모리 누적 가능성은 가설이며 실제 종료 원인으로 확인되지 않았다.

## 문서 대조

HJ Search 실제 호출은 HTTP 401 인증 오류로 실패했다. Apple 공식 문서로 보완:

- https://developer.apple.com/documentation/uikit/providing-access-to-directories
- https://developer.apple.com/documentation/foundation/nsfilecoordinator

Apple은 보안 범위 URL의 내용을 읽고 쓸 때 파일 조정자를 사용하도록 안내한다. 구현의 누락은 확인했지만, 이것이 실기기 정체의 유일한 원인임을 증명한 것은 아니다.

## 검증 범위

원본 ZIP과 정상 파일을 보존하는 취소/임시파일 정리, 삭제 결과의 지연 반영, 삭제 후 ZIP 복사, 474개 폴더/6683개 파일 테스트를 별도 생성 자료로 실행한다. 시뮬레이터 통과를 Lightning 리더기/SD 실기기 성공이나 속도 보증으로 표현하지 않는다. OS의 파일 I/O가 반환되지 않는 동안 협력적 취소도 기다릴 수 있다.

- 8494e83 / USB regression 34335173402: 삭제 후 474개 폴더/6683개 파일 ZIP 내보내기 통과 (소용량 합성 파일, 총 43초; 실제 10.38GB 속도 측정 아님).
- 같은 실행: 임시파일 정리 2개 테스트, 취소 UI 상태 테스트 통과.
- 같은 실행: 조정된 쓰기를 요구하는 provider 재현 조건에서 기존 USB 내보내기 실패 확인. 기본 디스크에서는 성공하므로 외부 파일 제공자 계약을 구분해서 점검.
- 6a5005f / CI 34333941222: 삭제 반영 지연 조건에서 65개 잔여 오표시 재현 확인. 재확인은 읽기만 수행하도록 변경했으며 재검증 중.
- 92c50da / USB regression 34335824331: 삭제 지연 65개 오표시 테스트를 포함한 삭제 테스트 11개 통과. 당시 남은 실패는 조정된 쓰기 테스트뿐.
- 609aa16 / USB regression 34336329143: 외부 제공자 쓰기 조정 테스트와 대량 구조 테스트 통과. 77개 중 1개 실패는 새로 추가한 SD 분리 후 정리 완료 오표시 테스트. 분리된 저장장치의 경로 부재를 삭제 성공으로 간주하던 처리에 저장장치 존재/동일성 확인을 추가하여 재검증한다.
