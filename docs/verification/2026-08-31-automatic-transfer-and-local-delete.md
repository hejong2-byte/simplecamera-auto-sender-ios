# 자동전송 점검 및 저장 파일 수동 삭제 검증

## 점검 범위

- 단축어 진입점, 명시적 재시도, 중복 실행 합치기, 사진 원본 읽기 및 판별.
- 업로드 장부의 발견/대기/실패/완료 상태와 재실행 복구.
- 자동·수동 전송의 진행률 및 PC 파일 수신 콜백 간 경계.
- HTTP 저장 응답, 서버·인증·네트워크 오류, 요청 취소 및 임시 파일 정리.
- 선택한 iPhone 저장 파일의 확인형 삭제와 목록/결과 표시.

운영 서버 배포, 서버 파일 삭제, 사용자의 수신 폴더·설정·인증값 초기화는 하지 않았다. Windows 수신기와 서버는 관련 완료·중복 처리 경로만 읽어 확인했다.

## 재현된 자동전송 오류와 수정

| 확인된 문제 | 수정 |
| --- | --- |
| 판별 전 후보 11개가 전송 대상 11장처럼 표시됨 | 후보 검사 개수와 실제 전송 개수를 분리 |
| 전송 대상이 없는데 0장 완료/100%로 표시됨 | 새 전송 대상 없음으로 표시, 빈 작업은 100% 처리하지 않음 |
| 빠른 종료 경로에서 제외 사진의 판별 결과가 장부에 남지 않음 | 판별 직후 제외 결과 기록, 다음 실행에서 반복 준비 방지 |
| 앱 종료 후 남은 queued 사진을 모든 재시도에서 건너뜀 | 다음 자동실행과 명시적 재시도에서 대기 사진 복구 |
| 한 사진 성공 후 조용한 재검색에서 아직 읽지 못한 원본을 포기함 | 알려진 미완료 원본이 있으면 예정된 재시도를 계속 수행 |
| 읽지 못한 메타데이터를 비대상으로 확정함 | 읽기 오류와 정상 비대상 판별을 구분, 읽기 오류는 재시도 가능 |
| 후속 검색 오류가 앞서 확인한 성공 수를 0으로 덮음 | 확인된 완료/실패 수를 보존하고 작업 오류를 별도로 표시 |
| 요청 취소가 사진 실패/네트워크 오류로 기록됨 | 일시중단으로 구분, 다음 자동실행에서 미완료 사진 재시도 |
| HTTP 저장 확인 뒤 임시 파일 정리 오류로 업로드가 실패 처리됨 | 저장 확인 상태를 유지하고 임시 파일 정리를 비치명적으로 처리 |
| 성공 후에도 이전 서버 오류와 실패 수가 화면에 남음 | 자동전송 종료 이벤트에서 장부 기반 결과를 다시 읽음 |
| 재시도 중 들어온 새 자동화 요청의 새 사진 검사가 누락될 수 있음 | 합쳐진 실행에서도 요청된 새 사진 검사를 수행 |

기존 해상도 및 iPhone 기기/렌즈 정보 필터, 단축어 식별자, 기준 시각은 유지한다. 한 장씩 전송하며 사진 수 상한을 두지 않는다. 수동 전송 완료 및 PC 파일 수신 콜백에 자동 사진 검사 호출을 추가하지 않았다.

## 수동 삭제의 범위

- PC 파일 수신 화면의 저장 파일 목록에서 선택 후 별도 확인을 거친다.
- 확인 대상은 선택 당시의 파일 목록으로 고정한다. 취소하면 삭제하지 않는다.
- 받은 파일 폴더의 일반 파일만 삭제한다. 폴더·심볼릭 링크·외부 경로는 거부한다.
- 선택 이후 크기, 수정 시각 또는 수신 기록이 달라진 파일은 보존한다.
- 수신 완료 ACK가 아직 남은 파일을 보호한다.
- 파일별 성공/실패를 따로 집계하고 남은 목록을 즉시 다시 읽는다.
- USB 및 PC의 복사본, 선택하지 않은 파일, 다운로드 중간 파일, 수신 이력은 지우지 않는다.
- “안전한 저장 방식” 안내 카드만 제거한다. 크기·SHA-256 검증은 유지한다.

## 재현 기록

- [초기 자동전송 회귀 테스트](https://github.com/hejong2-byte/simplecamera-auto-sender-ios/actions/runs/33349386501): 새 회귀 검사가 기존 구현에서 실패함을 확인했다.
- [핵심 수정 후 재검사](https://github.com/hejong2-byte/simplecamera-auto-sender-ios/actions/runs/33349963118): 자동전송 핵심 회귀 검사는 통과. 추가한 종료 후 이전 오류 표시 검사와 아직 제거하지 않은 안내 카드 검사만 실패했다. 로직 227개, UI 6개 실행.
- [수동 삭제 구현 전 검사](https://github.com/hejong2-byte/simplecamera-auto-sender-ios/actions/runs/33350621657): 아직 없는 삭제 API를 호출하는 신규 테스트가 컴파일 단계에서 실패했다. 삭제 동작 자체의 실패를 재현한 것으로 간주하지 않는다.

최종 통합 검사 및 IPA 검증 결과는 완료 후 이 문서에 기록한다.

## 한계

- 테스트는 격리된 임시 파일, 가짜 네트워크 응답 및 iOS 시뮬레이터를 사용한다. 실제 iPhone 14 Pro와 Lightning USB의 동작을 확인한 것은 아니다.
- 해상도와 기기/렌즈 정보만으로 촬영 앱의 출처를 완전히 증명할 수는 없다. 사용자가 지정한 판별 조건을 유지했다.
- 자동 사진 전송은 단축어가 앱을 열어 실행하는 기존 방식이다. 강제 종료 상태의 상시 자동전송을 새로 구현한 것이 아니다.
- 기존 iPhone 저장 파일을 보존하려면 앱을 삭제하지 말고 SideStore에서 업데이트 설치한다.
