# Simple Cam 완전 자동 전송 재설계

## 목표

사용자가 Simple Cam에서 사진을 몇 장 찍든 앱을 닫기만 하면, 새 Simple Cam 사진 전체가 별도 버튼 조작 없이 PC 수신기에 도착해야 한다. `지금 전송`은 정상 흐름에서 사용하지 않고 오류 복구용으로만 유지한다.

## 확정된 사용자 흐름

1. 사용자는 기존처럼 단축어 개인용 자동화의 조건을 `Simple Cam이 닫힐 때`로 둔다.
2. 자동화는 전송 앱의 새 전자동 전송 동작을 실행한다.
3. 전송 앱이 자동으로 전면에 열려 iOS의 백그라운드 전송 지연을 피한다.
4. 전송 앱은 기준 시각 이후 생성되었고 장부상 성공하지 않은 사진 전체를 찾는다.
5. 사진 저장이 늦는 경우 고정 15초를 기다리지 않고 PhotoKit 변화와 짧은 안정 구간을 관찰하여 새 사진이 보이는 즉시 처리한다.
6. 판별 조건을 통과한 모든 사진을 서버에 전송하고 각 HTTP 성공 응답을 확인한다.
7. 모든 항목의 결과가 확정되면 자동화가 홈 화면으로 돌아간다.

사용자가 촬영 때마다 전송 앱을 열거나 `지금 전송`을 누르는 과정은 없다.

## 사진 대상

이번 실행은 “최근 1장”이 아니라 자동 전송 기준 시각 이후 아직 성공 처리되지 않은 모든 사진을 검사한다. 사진 개수 제한을 두지 않는다.

사진은 다음 조건을 모두 만족할 때만 Simple Cam 사진으로 처리한다.

- 원본 픽셀 크기가 `6048 × 8064` 또는 `8064 × 6048`이다.
- TIFF 카메라 모델과 EXIF 렌즈 모델 어디에도 대소문자 구분 없이 `iPhone`이 없다.

앱 이름, 파일명, `Software` 메타데이터, 위치와 기타 촬영 정보는 판별에 사용하지 않는다. 기존 사진 장부와 위 판별기는 그대로 유지하여 일반 사진이 섞이지 않게 한다.

## 구조

### 전면 실행 App Intent

자동화용 App Intent는 앱을 전면에 연다. 기존처럼 백그라운드 업로드 작업을 등록하고 즉시 끝내지 않는다. 사진 검색과 실제 업로드가 끝날 때까지 실행을 유지한 후 결과를 반환한다.

### 사진 도착 관찰

검색기는 실행 즉시 미처리 후보를 조회한다. 이미 보이는 사진은 바로 처리하고, 마지막 촬영분이 아직 PhotoKit에 저장 중이면 변경 통지와 짧은 재확인을 사용한다. 후보 집합에 새 항목이 더해지지 않는 짧은 안정 구간이 지나면 해당 촬영 묶음이 완성된 것으로 본다.

고정 15초 전체 대기는 사용하지 않는다. 사진이 나타나는 시점에 즉시 다음 단계로 넘어간다. 비정상적으로 저장 통지가 오지 않는 경우에만 안전 제한으로 종료하고 다음 자동화나 오류 복구에서 다시 시도한다.

### 실제 완료를 기다리는 업로더

자동화 실행 중에는 전면 `URLSession` 파일 업로드를 사용하고 서버의 HTTP 응답을 기다린다. 여러 장은 메모리 사용을 제한하는 소수의 동시 작업으로 모두 처리한다. HTTP `2xx`를 받은 항목만 `uploaded`로 기록하고 임시 파일을 삭제한다.

`전송 N장`은 대기열 등록 수가 아니라 실제 서버 성공 수를 의미한다. PC 수신기는 기존 릴레이 계약을 그대로 사용하므로 수정하지 않는다.

### 자동 복구

네트워크 오류, 인증 오류 또는 앱 중단으로 완료되지 않은 항목은 성공으로 기록하지 않는다. 다음 Simple Cam 종료 자동화가 실행되면 이전 미완료 항목과 이번 새 항목을 함께 자동 재시도한다. `지금 전송` 버튼도 같은 미완료 항목을 재시도하지만 정상 사용에는 필요하지 않다.

## 자동화 구성

개인용 자동화는 다음 순서로 한 번만 설정한다.

1. 조건: `Simple Cam이 닫힐 때`
2. 동작: 전송 앱의 전자동 전송 App Intent
3. 동작: `홈 화면으로 이동`
4. 실행 방식: `즉시 실행`, 실행 확인 없음

기존 자동화에서 App Intent를 새 동작으로 바꾸고 홈 화면 이동을 한 번 추가해야 한다.

## 상태와 알림

- 성공: `N장 전송 완료`
- 대상 없음: `새 Simple Cam 사진 없음`
- 일부 실패: `N장 완료, M장 재시도 대기`
- 설정 오류: 사진 권한 또는 인증값 설정이 필요하다는 구체적 메시지

전송 완료 알림은 모든 대상의 HTTP 결과가 나온 뒤에만 표시한다.

## 오류 처리와 데이터 안전

- 성공한 사진만 중복 방지 장부에 완료로 기록한다.
- 실패한 사진은 다음 실행에서 자동 재시도한다.
- 판별하지 못한 원본은 업로드하지 않는다.
- 한 사진의 오류가 나머지 사진 전송을 막지 않는다.
- 인증값과 사진 내용은 로그에 기록하지 않는다.
- 기존 번들 식별자와 Keychain을 유지하여 재설치 후 설정과 장부 호환성을 보존한다.

## 시험 기준

자동 시험은 다음을 검증한다.

- 후보가 늦게 나타나도 고정 15초 없이 나타나는 즉시 처리한다.
- 1장, 여러 장, 기존 실패 항목과 새 항목의 혼합을 모두 전송한다.
- 사진 개수 제한이 없다.
- 실제 HTTP 성공 전에는 완료로 기록하거나 성공 수를 올리지 않는다.
- 일부 실패 시 성공 항목만 완료되고 실패 항목은 재시도 대상에 남는다.
- 기존 해상도와 `iPhone` 표식 판별 및 중복 방지 시험이 그대로 통과한다.

기기 시험 완료 조건은 다음과 같다.

1. Simple Cam으로 1장을 찍고 닫으면 버튼 없이 PC에 정확히 1장이 도착한다.
2. Simple Cam으로 여러 장을 찍고 한 번 닫으면 새 사진 전체가 PC에 각각 한 번만 도착한다.
3. iPhone 기본 카메라 사진과 스크린샷은 전송되지 않는다.
4. 네트워크를 끊고 촬영한 뒤 복구하여 다음 자동화에서 미완료 사진이 자동 전송된다.
5. 알림의 완료 수와 PC 도착 수가 일치한다.
