# 전송 취소 및 저장 위치 변경

## 승인된 사용자 요구

- 전송 상태 옆에 전송 취소, 저장 위치 변경 버튼을 제공한다.
- 취소는 실패와 구분한다. 원본과 이미 완료된 파일을 보존한다.
- 새 저장 위치는 미완료 파일에만 적용한다.
- SD 카드의 전체 내용 삭제 기능을 설정에서 사용할 수 있어야 한다.

## 적용 범위

수동 사진·스크린샷·동영상·파일 송신, PC 파일 수신, iPhone 저장 파일의 USB 복사에 적용한다. 텍스트 메시지의 전송 취소나 이미 서버에 완료된 송신의 회수는 포함하지 않는다. Simple Cam 자동 사진 전송 필터와 기동 로직은 이 기능 변경에서 수정하지 않는다.

## 취소

1. 표시 중인 송신 묶음 또는 사용자가 승인한 미완료 수신 묶음을 취소 대상으로 고정한다. 다른 작업과 완료 파일을 포함하지 않는다.
2. 취소 중에는 중복 입력을 막고 '취소 중'을 표시한다.
3. 백그라운드 작업 취소보다 먼저 중단 의사를 영속화한다. 이후 들어오는 진행률·완료·재시도 응답은 작업 식별자와 중단 상태를 확인한다.
4. 취소한 묶음의 준비 작업과 대기 작업도 신규 네트워크 작업을 생성하지 않는다. 앱 재실행과 백그라운드 복원에서도 자동으로 재개하지 않는다.
5. 실제 중단 확인 뒤 '취소됨'을 표시한다. 실패 수에 합산하지 않는다. 영속화 또는 중단 실패 시에는 취소 완료라고 표시하지 않는다.
6. 서버 완료나 검증된 최종 저장이 이미 확정된 파일은 완료로 유지한다. 취소는 되돌리기가 아니다.
7. 사용자 원본, 기존 USB 파일, 완료된 수신 파일은 삭제하지 않는다. 새로 생성한 미완료 임시 파일만 작업 소유권을 확인해 정리할 수 있다. 취소 때문에 서버 수신 원본에 완료 ACK를 보내지 않는다.

## 저장 위치 변경

- 수신 또는 USB 복사 작업에서만 제공한다. 송신에는 저장 위치 버튼을 표시하지 않는다.
- 기존 쓰기 작업을 안전하게 멈춘 뒤 iPhone 또는 USB/SD 폴더를 선택한다. 동일 시점에 두 저장 위치로 쓰지 않는다.
- 폴더 선택을 취소하면 중단 상태를 유지한다. 이전 위치로 자동 재개하지 않는다.
- 새 위치의 권한·연결·쓰기 가능 여부를 확인한 뒤 미완료 파일만 재개한다. 위치가 달라 기존 부분 파일을 안전하게 재사용할 수 없다면 처음부터 다시 받고 진행률을 초기화한다.
- 다운로드가 완료된 iPhone 원본을 USB로 복사할 때에는 원본을 그대로 재사용한다. 완료된 다른 파일을 이동하거나 삭제하지 않는다.
- ZIP 처리 선택(그대로 저장/압축 해제)을 보존한다. 기존 ZIP 해제 경로가 USB 전용이면 iPhone 대상으로 강제 변환하지 말고 ZIP 그대로 저장 여부를 명시적으로 다시 확인한다.
- 최종 저장 확정·ACK 처리 중에는 위치 변경을 허용하지 않는다. 중단 가능한 다음 상태까지 '마무리 중'을 표시한다.

## SD/USB 전체 내용 삭제

기존 USBStorageManagementView와 USBFolderCleanupService를 재사용한다. 설정의 SD/USB 저장장치 관리에서 카드 최상위 폴더를 고르면 카드 내용 전체를 대상으로 한다. 하위 폴더를 고르면 그 하위 폴더 내용만 대상이다. 포맷 기능은 추가하지 않는다.

삭제 전 선택 폴더명, 파일·폴더 수, 용량을 표시하고 최종 확인을 받는다. 전송·복사·위치 변경과 동시에 삭제하지 않는다. 확인 후 저장장치나 내용이 변경되면 재확인을 요구한다. 선택 폴더 자체와 iPhone 원본은 유지하며, 성공/남은 항목/실패를 구분해 표시한다. 실제 사용자 SD 파일은 개발 검증에 사용하지 않는다.

## 변경 경계

- 송신: ManualMediaTransferService, ManualBackgroundTransferEngine, ManualTransferJobStore, ContentViewModel 및 상태 카드.
- 수신: IPhoneLocalReceiveEngine, USBReceiveService, 수신 승인·작업 저장소, USBReceiverViewModel 및 상태 카드.
- 복사: IPhoneUSBExportService 및 ZIP 복사 루프의 중단 경계.
- 조립: AppDependencies, USBReceiverDependencies의 취소/재개 연결.
- UI: 확인창과 상태 문구만 추가한다. 기동 시 새 창 자동 표시나 기동 데이터 초기화를 추가하지 않는다.

## 검증 기준

1. 송신 묶음의 진행/대기/파일 준비 중 취소가 다른 묶음 및 원본에 영향을 주지 않는다.
2. 취소 후 늦은 성공/실패 응답과 예약 재시도가 새 작업이나 완료 ACK를 만들지 않는다.
3. 취소 상태를 저장한 뒤 프로세스를 다시 생성해도 자동 재시작하지 않는다.
4. 저장 위치 변경 중 폴더 선택 취소, USB 분리, 권한 오류 시 이전 위치에 계속 쓰지 않는다.
5. 완료 파일은 그대로 남고 미완료 파일만 새 위치로 처리된다. ZIP 그대로/압축 해제 양쪽을 확인한다.
6. SD 삭제는 격리된 임시 디렉터리에서 숨김·중첩 항목, 다른 폴더 보존, 동시 전송 차단을 확인한다.
7. 기존 전체 단위/UI 테스트와 iOS 26 Release 시뮬레이션, IPA 빌드 및 버전 검사를 통과한 뒤 설치본을 제공한다. 실제 iPhone/USB 검증과 시뮬레이터 결과를 구분한다.
