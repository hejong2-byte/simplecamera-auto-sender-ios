# 자동전송 실시간 진행률 설계

## 목표

Simple Cam을 닫아 자동화가 실행되면 전송 앱에서 자동전송 상황을 즉시 확인할 수 있어야 한다. 사용자는 별도 버튼을 누르지 않고 다음 정보를 본다.

- 현재 단계
- 현재 사진 번호와 전체 사진 수
- 실제 전송 바이트 기준 프로그레스바와 퍼센트
- 전송 용량
- 완료·실패 사진 수와 실패 원인

## 확정된 전송 방식

자동전송 대상 사진 수에는 제한을 두지 않는다. 사진은 동시에 보내지 않고 생성 시각 순서로 한 장씩 전송한다. 현재 사진이 서버 성공 또는 실패로 확정된 뒤 다음 사진을 시작한다. 한 사진이 실패해도 다음 사진은 계속 처리하며, 실패 사진은 기존 장부에 남겨 다음 자동화에서 재시도한다.

순차 전송은 최고 속도보다 안정성, 진행 상황의 명확성, 서버 부하 감소를 우선한다. 수동 사진·스크린샷·동영상 전송 방식은 변경하지 않는다.

## 화면

메인 화면에서 수동전송 영역보다 위에 `자동전송 상태` 카드를 둔다. 자동화로 앱이 열리면 다음 순서로 표시한다.

1. `새 사진 확인 중`
2. `원본 준비 중 · 3/10장`
3. `PC로 전송 중 · 3/10장`
4. `서버 저장 확인 중 · 3/10장`
5. `자동전송 완료 · 10장` 또는 실패가 포함된 결과

전송 중 카드에는 프로그레스바, 큰 퍼센트 숫자, `전송 바이트 / 현재 확인된 전체 바이트`, 완료·실패 개수를 표시한다. 서버 오류, 네트워크 오류, 인증 오류와 원본 읽기 오류는 기존 분류를 사용해 빨간색으로 표시한다.

자동전송이 시작되지 않은 평상시에는 카드를 간단한 대기 상태로 유지한다. 완료 또는 실패 결과는 다음 자동전송이 시작될 때까지 남긴다.

## 퍼센트 계산

퍼센트는 사진 개수가 아니라 실제 바이트를 사용한다.

`전체 진행률 = (완료된 사진 바이트 + 현재 사진에서 서버로 보낸 바이트) / 현재 확인된 자동전송 사진 전체 바이트`

현재 사진의 바이트 전송량은 `URLSessionTaskDelegate`의 업로드 콜백에서 받는다. 완료 응답을 받기 전에는 해당 사진을 완료로 계산하지 않는다. 새 사진이 늦게 발견되어 전체 바이트가 늘면 정확한 계산을 위해 퍼센트가 잠깐 내려갈 수 있다.

## 구조와 데이터 흐름

자동전송 전용 진행 값과 진행 저장소를 둔다. 진행 값에는 단계, 현재 사진 번호, 전체 사진 수, 완료·실패 수, 전체 바이트, 전송된 바이트와 실패 원인이 포함된다.

진행 저장소는 마지막 값을 보관하고 변경 이벤트를 전달한다. App Intent가 먼저 전송을 시작하고 화면이 조금 늦게 만들어져도 화면은 마지막 값을 즉시 받아 현재 상태부터 표시한다.

`PhotoSyncService`는 사진 검색, 원본 준비, 사진별 시작·완료·실패와 전체 종료 상태를 게시한다. `BackgroundUploadCoordinator`는 현재 파일의 실제 전송 바이트를 게시한다. 자동전송 진행 상태는 기존 자동 사진 장부와 수동전송 작업 저장소에 기록하지 않아 전송 대상이나 중복 방지 데이터를 오염시키지 않는다.

## 오류와 복구

- 서버 `5xx` 등 HTTP 실패는 `서버 오류`로 표시한다.
- 연결 실패는 `네트워크 오류`, 인증 거부는 `인증 오류`, 원본 내보내기 실패는 `원본 읽기 오류`로 표시한다.
- 실패 사진은 성공으로 계산하지 않고 다음 실행의 재시도 대상으로 유지한다.
- 같은 사진이 나중에 성공하면 기존 실패 표시와 실패 개수에서 제거한다.
- 앱이 실행 중인 전송과 화면의 진행 이벤트가 같은 자동전송 실행을 가리키도록 실행 식별자를 사용한다.

## 시험 기준

자동 시험은 다음을 검증한다.

- 여러 사진을 자동전송할 때 동시에 활성화되는 자동 업로드는 정확히 한 장이다.
- 실제 업로드 바이트 이벤트가 전체 퍼센트와 용량 문구에 반영된다.
- 성공 응답 전에는 완료 수가 증가하지 않는다.
- 한 사진 실패 후 다음 사진이 계속 전송된다.
- 서버 오류가 진행 카드에 `서버 오류`로 표시된다.
- 화면이 늦게 구독해도 마지막 자동전송 진행 상태를 즉시 받는다.
- 수동전송 진행 상태와 자동전송 진행 상태가 서로 섞이지 않는다.
- 기존 Simple Cam 판별, 중복 방지와 전체 테스트가 그대로 통과한다.

실기기에서는 Simple Cam으로 1장과 여러 장을 각각 촬영해 앱을 닫고, 버튼 조작 없이 진행률이 움직이며 PC 도착 수와 완료 수가 일치하는지 확인한다.

## 배포

기존 번들 식별자와 SideStore 설치 주소를 유지한다. 빌드 번호를 올리고 iOS 전체 CI와 IPA 내부 버전·원격 해시를 검증한 뒤 기존 테스트 QR 주소의 IPA를 교체한다.
