# 사진·스크린샷·동영상 수동 전송 설계

## 목표

기존 Simple Cam 자동 전송은 그대로 유지하면서, 사용자가 iPhone 앱을 직접 열어 사진·스크린샷·동영상을 시스템 선택창에서 여러 개 선택해 PC로 전송할 수 있게 한다. 자동 검색이나 출처 추정 없이 사용자가 고른 항목만 전송한다.

## 확정된 화면

메인 화면에는 다음 기능을 둔다.

1. `사진 전송`: 기본 카메라 사진을 포함한 사진 보관함 이미지를 다중 선택한다.
2. `스크린샷 전송`: PhotoKit이 스크린샷으로 분류한 이미지만 다중 선택한다.
3. `동영상 전송`: 사진 보관함 동영상만 다중 선택한다.
4. `설정`: 기존 초기 설정과 자동 전송 관리 화면으로 이동한다.

설정 화면에는 기존 기능을 다음 순서로 유지한다.

1. 사진 접근
2. 전송 인증 설정
3. 자동 전송 시작
4. 아이폰 자동화 1회 설정

자동 전송 상태, `지금 전송`, 실패 재시도와 초기화도 설정 화면에서 제공한다. 메인 화면에는 수동 전송 진행 여부와 직전 결과만 간결하게 표시한다.

## 선택과 데이터 경계

- Apple의 시스템 사진 선택기를 사용하며 선택 개수는 제한하지 않는다.
- `사진 전송`은 이미지 필터를 사용하므로 기본 카메라 사진과 스크린샷을 모두 볼 수 있다.
- `스크린샷 전송`은 전용 스크린샷 필터를 사용한다.
- `동영상 전송`은 동영상 필터를 사용한다.
- 선택 결과의 PhotoKit 로컬 식별자만 처리하며 보관함 전체를 스캔하지 않는다.
- 내보내기 직전에 자산 종류를 다시 검사해 버튼 종류와 맞지 않는 자산을 거부한다.
- 원본 파일명, 원본 형식과 촬영시각을 유지한다.
- 인증값, 사진 내용과 위치 정보는 로그에 남기지 않는다.

## iPhone 전송 구조

`ManualMediaPicker`가 시스템 선택기 결과를 전달하고, `ManualMediaTransferService`가 선택된 자산을 원본 임시 파일로 내보낸다. 서비스는 각 파일의 SHA-256, 크기, MIME 형식, 원본 파일명과 촬영시각을 업로더에 전달한다.

기존 자동 전송은 `/api/shortcut/photos` POST 경로를 그대로 사용한다. 수동 전송은 무결성 메타데이터가 포함된 `/api/photos/{id}` PUT 경로를 사용한다. 원격 ID는 파일 해시에서 결정적으로 만들어 재시도 중복을 방지한다.

성공한 임시 파일만 업로더가 제거하며, 실패한 임시 파일도 수동 서비스가 정리한다. 한 파일의 실패는 같은 선택 묶음의 나머지 파일 전송을 막지 않는다. 완료 뒤 성공·실패 개수를 화면에 표시한다.

## 서버와 크기 제한

기존 서버는 JPEG·PNG·HEIC·HEIF만 받고 20MiB에서 차단하므로 수동 동영상을 위해 다음을 추가한다.

- 허용 동영상: QuickTime MOV와 MP4
- 수동 파일 최대 크기: 2GiB
- 기존 자동 사진 POST 한도: 20MiB 유지
- 95MiB 이하 수동 파일은 단일 스트리밍 PUT을 사용할 수 있다.
- 큰 동영상은 약 32MiB 단위의 R2 멀티파트 업로드로 나누고 마지막에 서버에서 조립한다.
- 각 조각은 Worker 요청 한도 아래이며 Worker와 iPhone 메모리에 전체 동영상을 올리지 않는다.
- 서버는 인증, 허용 MIME 형식, 파일 크기, UUID·SHA-256 형식을 검사한다.
- PC 수신기가 다운로드 후 실제 크기, SHA-256과 파일 서명을 다시 검사한다.

Cloudflare Free/Pro의 단일 요청 본문은 100MB까지이므로 각 조각을 32MiB로 제한한다. R2 멀티파트의 조각 최소 크기 5MiB도 충족한다. 일반적인 300~400MB 동영상은 10여 개 조각으로 전송되며, 2GiB를 넘는 파일만 앱에서 네트워크 요청 전에 거부한다. 업로드 실패 시 진행 중인 멀티파트를 중단하고 선택 묶음의 다음 파일을 계속 처리한다.

## PC 수신기 동작

- 사진은 기존처럼 저장, 무결성 검사, 썸네일/미리보기와 클립보드 준비를 수행한다.
- 동영상은 MOV/MP4 서명과 크기·해시를 검사한 뒤 저장한다.
- 동영상은 클립보드 이미지 준비 대상에서 제외한다.
- 목록과 썸네일 격자에는 동영상 파일명, 수신시각, 크기와 형식이 나타난다. 이미지 디코딩이 불가능한 동영상 타일은 기본 자리표시자를 사용한다.
- 동영상은 `열기` 기능으로 Windows 기본 동영상 앱에서 실행할 수 있다.
- 기존 상태 DB와 사진 기록은 삭제하거나 재작성하지 않는다.

## 오류 처리

- 사진 전체 접근이나 인증값이 없으면 선택 전에 설정 화면에서 필요한 조치를 안내한다.
- iCloud 원본 다운로드 실패, 파일 내보내기 실패, 2GiB 초과, 인증 거부, 네트워크 오류를 서로 구분해 사용자 문구로 표시한다.
- HTTP 2xx를 받은 파일만 성공으로 센다.
- 서버나 PC 무결성 검사에 실패한 파일은 저장 완료·ACK 처리하지 않는다.
- 기존 Simple Cam 자동화 App Intent 이름과 번들·Keychain 식별자는 바꾸지 않는다.

## 검증 기준

1. 각 버튼이 대응하는 시스템 선택 필터를 열고 여러 항목을 반환한다.
2. 기본 카메라 사진, 스크린샷, MOV, MP4 샘플이 각각 PC에 원본 이름과 형식으로 저장된다.
3. 선택하지 않은 사진과 동영상은 전송되지 않는다.
4. 잘못된 종류, 변조된 파일과 2GiB 초과 파일은 성공 처리되지 않는다.
5. 사진과 동영상이 같은 수신 묶음에 있어도 사진만 클립보드에 준비된다.
6. 기존 Simple Cam 닫기 자동화와 자동 사진 전송 시험이 그대로 통과한다.
7. 기존 PC 사진 썸네일·정렬·다크 모드 시험이 그대로 통과한다.

## 배포 경계

앱 버전은 `0.1.7` / 빌드 `5`로 올린다. 소스와 자동 시험을 먼저 완성한다. Worker 배포, IPA 게시, SideStore QR 교체는 검증 뒤 별도 배포 단계에서 수행한다.
