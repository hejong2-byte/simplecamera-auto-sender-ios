# SimpleCamera iPhone 텍스트 송수신 및 홈 설명 정리

## 목표

iPhone 앱에서 Windows SimpleCamera의 기존 `simplecamera-text-v1` 규격으로 텍스트를 주고받는다. 기존 6자리 수신코드를 그대로 사용하고, 송수신 기록을 앱을 다시 실행한 뒤에도 보존한다. 동시에 홈 화면 메뉴 아래의 고정 설명 두 문구를 제거하되 진행률·완료·오류·수신 대기 같은 동적 상태 정보는 유지한다.

## 범위

### 홈 화면

- 수동 전송 카드의 `여러 개 선택 가능 · 큰 파일은 32MB씩 나눠 백그라운드 전송합니다. 카카오톡 파일 폴더는 처음 한 번 지정합니다.` 문구를 제거한다.
- PC 파일 수신 카드의 `PC에서 보낸 파일을 iPhone에 저장하거나 USB로 직접 저장` 문구를 제거한다.
- 사진·스크린샷·동영상·카카오톡 파일 버튼 아래에 `텍스트 송수신` 메뉴를 추가한다.
- 자동전송 상태, 전송 진행률, 전송 결과, PC 파일 수신 상태, 오류, 수신코드는 그대로 표시한다.
- 새 텍스트가 있으면 `텍스트 송수신` 메뉴에 확인하지 않은 건수를 표시한다.

### 텍스트 송수신 화면

- 자신의 6자리 수신코드를 표시한다.
- 받는 6자리 코드와 최대 1 MiB의 텍스트를 입력해 보낸다.
- 앱이 활성화되거나 전면으로 돌아오면 즉시 확인하고, 앱이 전면에 있는 동안 주기적으로 새 텍스트를 확인한다. 텍스트 화면에서는 사용자가 직접 새로고침할 수도 있다.
- 송신 전 원문을 로컬 기록에 `전송 대기`로 먼저 저장한다. 서버가 저장을 확인하면 `서버 전달 완료`로 바꾼다. 상대 기기가 실제로 수신했다고 단정하지 않는다.
- 받은 원문은 로컬에 원자적으로 저장한 뒤에만 서버 ACK를 보낸다.
- 송수신 기록에는 방향, 상대 코드, 시각, 상태, 원문 미리보기를 표시한다.
- 기록을 열어 원문 전체 보기, 전체 복사, UTF-8 TXT 저장·공유, 개별 삭제를 할 수 있다.
- 받은 기록을 실제로 열었을 때만 확인한 것으로 표시하며, 단순 수신만으로 홈 화면의 미확인 건수를 지우지 않는다.
- 기록을 선택하거나 수신하는 것만으로 클립보드를 덮어쓰지 않는다.

## 호환 전송 규격

- 형식: `simplecamera-text-v1`
- MIME: `application/vnd.simplecamera.text+json`
- 텍스트 전용 사서함: `53435458-0000-4000-8000-000000{6자리 코드}`
- JSON 필드: `format`, `id`, `sender`, `recipient`, `created_at`, `text`
- 메시지 ID는 UUID v4, 시각은 시간대가 포함된 ISO 8601, 원문은 UTF-8이며 공백·줄바꿈·탭을 보존한다.
- NUL 문자, 빈 문자열, 1 MiB 초과 원문, 잘못된 코드·UUID·시각·필드·해시·크기는 거부한다.
- 업로드는 기존 multipart/list/download/ACK 저장 구조를 재사용한다.

## 인증과 서버 연결

Windows 클라이언트와 기존 텍스트 사서함은 변경하지 않는다. iPhone 송신은 앱에 이미 저장된 업로드 인증을 사용한다. iPhone 수신은 PC 공용 수신 토큰을 기기에 저장하지 않고, 현재 iPhone 수신 등록의 `receiverID`와 `receiveSecret`을 사용하는 전용 서버 통로를 추가한다.

송신자 코드와 수신 권한에 현재 iPhone 등록이 필요하므로 등록 전에는 텍스트 송수신을 시작하지 않고 설정의 iPhone 수신 등록으로 안내한다.

서버는 등록된 iPhone의 6자리 코드에서 텍스트 사서함을 결정하고 해당 사서함의 텍스트 MIME 항목만 목록·다운로드·ACK하도록 제한한다. 다른 코드나 일반 파일은 이 통로로 읽을 수 없다. 인증 실패, 코드 불일치, 지원하지 않는 MIME은 서버 원본을 삭제하지 않는다.

## 로컬 보존 방식

- Application Support 아래 전용 디렉터리에 메시지별 JSON을 원자적으로 저장한다.
- 송신 대기 원문도 전송 전에 저장해 네트워크 실패나 앱 종료 뒤 재시도할 수 있게 한다.
- 같은 ID와 같은 해시는 중복 저장하지 않는다. 같은 ID인데 내용이 다르면 오류로 처리하고 서버 원본을 보존한다.
- 수신 기록을 사용자가 삭제하면 ID와 본문 해시만 담은 삭제 표식을 보존해 ACK 지연으로 삭제한 원문이 다시 나타나지 않게 한다.
- 작성 중 텍스트와 받는 코드는 별도 초안으로 보존한다.
- 기존 사진 전송 원장, Simple Cam 전용 필터, PC 파일 수신 기록, 인증정보는 변경하지 않는다.

## 화면 상태와 오류

- 상태는 `전송 대기`, `전송 중`, `서버 전달 완료`, `수신 확인 중`, `새 텍스트 수신`, `오류`로 구분한다.
- 인증 없음, 네트워크, HTTP 상태, 형식 오류, 저장 실패를 사용자가 구분할 수 있는 문구로 표시한다.
- 전송 실패 시 원문과 송신 기록을 보존하고 재시도 동작을 제공한다.
- 수신 저장 실패나 검증 실패 시 ACK하지 않는다.
- 앱이 백그라운드나 종료 상태일 때 실시간 수신을 보장한다고 표시하지 않는다. 앱이 다시 활성화되면 즉시 확인한다.

## 구현 경계

- iPhone 앱에는 텍스트 모델, 검증·인코딩, 로컬 저장소, 네트워크 클라이언트, 화면 모델, SwiftUI 화면을 각각 분리한다.
- 기존 `ContentView`에는 설명 제거, 메뉴 연결, 미확인 건수 표시만 추가한다.
- 서버에는 iPhone 등록 인증으로 텍스트 사서함을 읽는 최소 경로만 추가한다.
- Windows 텍스트 클라이언트, 사진 자동전송 필터, 일반 파일 송수신 API는 수정하지 않는다.

## 검증 기준

- Windows 구현에서 만든 고정 JSON과 iPhone 인코더가 원문·필드·해시까지 상호 호환된다.
- 한글, 이모지, 앞뒤 공백, 줄바꿈, 탭이 송신·서버·수신·재실행 뒤에도 동일하다.
- 1 MiB 경계, 잘못된 코드·형식·해시·크기, 인증 실패, 저장 실패, 중복, 삭제 후 재등장을 테스트한다.
- 서버 테스트에서 한 iPhone의 비밀키로 다른 코드의 텍스트나 일반 파일을 읽을 수 없음을 확인한다.
- UI 테스트에서 고정 설명 두 문구가 사라지고, 동적 상태와 기존 메뉴가 남으며, 텍스트 메뉴·입력·기록·복사·저장·삭제가 동작함을 확인한다.
- 기존 iOS 단위 테스트, UI 시뮬레이션, 서버 테스트를 모두 다시 실행한다.
- 새 버전 IPA 내부 버전·번들 ID·파일 무결성과 설치 QR 대상을 검증한 뒤 배포한다.

## 제외 범위

- 푸시 알림과 종료 상태의 실시간 텍스트 수신
- 자동 클립보드 덮어쓰기
- 여러 수신자 동시 발송
- 대화방, 읽음 확인, 상대 기기 수신 완료 확인
- Windows 화면이나 기존 텍스트 데이터베이스 변경
