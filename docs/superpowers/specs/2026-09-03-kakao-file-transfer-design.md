# 카카오톡 저장 파일 수동전송 설계

## 승인된 범위

사용자는 `동영상 전송` 바로 아래에 `카카오톡 파일전송` 버튼을 추가하고,
최초 한 번 파일 앱에서 폴더를 지정한 뒤 기본 위치로 기억하는 방식을 승인했다.
카카오톡 내부 보관함을 자동으로 읽는 기능이 아니라, 파일 앱에 저장해 둔 파일 중
사용자가 직접 선택한 항목을 기존 연결 PC로 보내는 기능이다.

기존 저장 파일 열기 및 수신 기기 카드 제거 설계는 취소하거나 대체하지 않는다.
해당 범위는 `2026-09-01-stored-file-preview-and-receiver-cleanup-design.md`에 유지한다.

## 화면과 사용 흐름

1. 기존 사진·스크린샷·동영상 버튼의 순서와 스타일을 유지하고 그 아래에
   `카카오톡 파일전송` 버튼을 추가한다.
2. 기본 폴더가 없으면 iOS 시스템 폴더 선택기를 연다. 파일 앱에 카카오톡 저장
   폴더가 보이면 그 폴더를 고른다. 없다면 카카오톡 파일을 파일 앱으로 내보내
   저장한 폴더를 고르도록 안내한다. 존재하지 않는 카카오톡 경로를 만들지 않는다.
3. 폴더 선택이 완료되면 접근 권한을 포함한 북마크를 저장하고 파일 선택기를 연다.
   다음 실행부터도 이 폴더를 기본 시작 위치로 지정한다. iOS가 해당 시작 위치를
   사용하지 못하는 경우 현재 위치를 숨기거나 다른 폴더를 카카오톡 폴더라고 표시하지 않는다.
4. 파일은 여러 개 선택할 수 있다. 폴더 지정만으로는 업로드하지 않는다.
   파일 선택을 취소하면 전송 작업과 완료·실패 건수를 만들지 않는다.
5. 설정에 현재 기본 폴더 이름과 `폴더 다시 선택`을 제공한다. 폴더 변경은 이 기능의
   기본 위치만 바꾸며 USB 저장 위치나 기존 전송 인증값에는 영향을 주지 않는다.

파일 선택기는 사진 보관함이 아닌 시스템 문서 선택기를 사용한다. ZIP, PDF, 한글,
Office 문서, 이미지, 동영상 등 일반 파일을 선택할 수 있게 한다. 폴더 자체를
업로드하거나 폴더 전체를 자동으로 순회해 보내지 않는다.

폴더 선택·파일 선택·오류 안내가 표시된 동안 새 PC 파일 도착 안내가 그 위에 겹쳐
나오지 않도록 기존 안내 표시 조건에 연결한다. 실제 수신 대기 기록은 지우지 않는다.

## 폴더 접근과 원본 보존

- 기본 폴더 북마크는 USB 북마크와 다른 저장 위치에 보관한다. 앱 재실행 후 복원한다.
- 사용자가 허용한 폴더·파일만 security-scoped URL로 접근하고 파일 읽기를 조정한다.
  모든 읽기 성공·실패 경로에서 접근 권한 사용을 종료한다.
- 권한 철회, 폴더 이동·삭제, 복원 불가능한 북마크는 `폴더에 접근할 수 없습니다`로
  표시하고 다시 선택하게 한다. 접근 실패를 빈 폴더나 전송 성공으로 취급하지 않는다.
- 선택된 원본은 읽기 전용으로 다룬다. 삭제·이동·이름 변경·압축·이미지 변환을 하지 않는다.
- 백그라운드 전송을 위해 선택 파일만 앱의 전송 준비 영역에 복사한다. 준비 복사본과
  분할 조각만 기존 작업 정리 규칙으로 삭제하며 사용자 원본은 삭제 대상이 아니다.
- 클라우드에만 있는 파일은 공급자가 내용을 제공한 뒤 준비한다. 파일이 없어지거나
  읽지 못하면 해당 파일의 준비 실패로 표시하고 다른 선택 파일과 혼동하지 않는다.

## 전송 구조와 호환성

`ContentView`는 새 버튼과 폴더·문서 선택기의 표시만 담당한다. 별도 폴더 북마크 저장소와
문서 입력 경로가 선택 URL을 안전한 준비 복사본으로 만들고, 기존 수동전송 큐에 넘긴다.
파일 입력 때문에 기존 `PhotoKit` 사진 선택 경로를 대체하지 않는다.

일반 파일 전송에는 기존 전송 인증값을 사용하되 사진 전체 접근 권한은 요구하지 않는다.
자동전송 기준 시각, Simple Cam 식별 필터, 사진 처리 기록에는 항목을 추가하거나
초기화를 하지 않는다. 기존 큐의 사진·스크린샷·동영상 작업도 계속 복원 가능해야 한다.

준비 완료 후에는 기존 백그라운드 업로드, 재시도, 해시 검증과 진행률 표시를 재사용한다.
원본 파일명·확장자·내용을 보존하고 실제 MIME 유형을 사용한다. 알 수 없는 유형은
`application/octet-stream`으로 처리하며 문서를 사진으로 위장하지 않는다.
기존 수동전송의 파일당 2 GiB 상한, 95 MiB 단일 요청 기준, 32 MiB 분할 크기를 유지한다.

로컬에서 확인한 예전 relay 소스의 iPhone 수동 업로드 경로는 미디어 유형만 허용한다.
따라서 버튼만 추가해서 완료로 간주하지 않는다. 구현 단계에서 실제 배포에 대응하는
relay 소스를 확인하고 일반 파일 업로드 계약까지 연결·검증한다. 일반 파일 허용은
수동 파일 경로에 한정하며 자동 사진 업로드의 형식 검증을 느슨하게 만들지 않는다.
구버전 Windows 소스로 운영 수신기를 덮어쓰거나 운영 파일·설정·인증값을 초기화하지 않는다.

## 상태와 오류

- 기존 수동전송 상태 영역에서 `파일 준비 중`, `전송 중`, `재시도 대기`, `전송 완료`,
  `전송 실패`를 구분하고 선택·완료·실패 개수, 바이트와 퍼센트를 표시한다.
- 폴더 접근, 원본 읽기, 준비 공간 부족, 용량 초과, 인증, 네트워크, 서버 거부를 구분한다.
  실패한 파일을 완료로 세지 않고 폴더 문제를 사진 권한 문제라고 안내하지 않는다.
- 서버 접수가 끝나야 업로드 완료로 표시한다. PC의 실제 저장 확인이 없으면
  `PC에 저장 완료`라고 표시하지 않는다.
- 준비 복사가 끝나기 전과 전송을 시작한 뒤를 구분한다. 시작된 업로드는 기존
  iOS 백그라운드 전송 방식으로 처리하되 강제 종료 후 즉시 전송을 보장하지 않는다.

## 검증과 완료 기준

실제 업무자료 대신 임시 폴더와 테스트 파일로 먼저 실패 테스트를 작성한다.

1. 버튼이 동영상 아래에 배치되고 기존 세 버튼은 그대로 동작한다.
2. 첫 실행·취소·북마크 저장·재실행 복원·권한 철회·폴더 다시 선택을 검증한다.
3. 선택하지 않은 파일은 전송하지 않으며 원본 해시·크기가 전송 준비 후에도 동일하다.
4. 사진 권한이 없어도 인증된 일반 파일 전송은 시작할 수 있고, 기존 사진 전송 권한
   검사는 그대로 유지한다.
5. 한글 파일명, ZIP/PDF/HWPX, 같은 이름의 서로 다른 파일, 읽기 실패, 용량 초과,
   300 MiB 수준의 분할 전송과 재시도·재실행 복원을 검증한다.
6. 서버의 일반 파일 수락·거부, 크기·SHA-256 검증, PC 수신 파일의 이름·내용 보존을
   격리 환경에서 확인한다. UI 테스트만으로 실제 PC 수신 성공을 주장하지 않는다.
7. 전체 iOS 테스트와 빌드를 통과하고 기존 자동전송·PC 수신·USB 복사·수동 삭제의
   동작 및 운영 데이터가 유지되는지 확인한다.

실물 아이폰의 카카오톡 폴더 노출 여부와 파일 공급자 권한 복원은 별도 기기 확인 사항이다.
이 문서는 설계이며 구현·빌드·배포 완료의 증거로 사용하지 않는다.
